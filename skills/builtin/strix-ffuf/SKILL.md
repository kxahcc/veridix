# Content Discovery with FFUF

## Objective
Discover hidden directories, files, virtual hosts and parameters with a
controlled wordlist, then triage results before reporting.

## When to use
- The application surface is known but paths are undocumented.
- Directory brute force is authorized and rate limits permit it.

## Steps
1. Choose a wordlist matched to the technology and a seed URL from observed
  routes.
2. Run `web.ffuf.scan` with a strict status/filter set and a bounded rate.
3. Triage by status code, content length and technology; ignore obvious
  catch-all pages.
4. For interesting paths, request them directly and record the response.

## Verification
- A discovered path is not a finding by itself; it becomes a finding when it
  exposes data or a vulnerable behavior.
- Confirm the path is not generated by a soft-404 or virtual host fallback.

## Evidence
Save wordlist, filters, matched paths, response status/length and direct
request evidence for candidate paths.

## Risk notes
Use small wordlists on live targets and stop after useful paths are found.
