# Veridix 系统说明

## 一句话介绍

Veridix 是一套面向授权安全测试与漏洞验证的 AI Agent 平台。它不是一个只会聊安全知识的聊天机器人，而是一个能够真正理解任务、调用真实安全工具、验证漏洞、沉淀证据并交付报告的智能测试系统。

## 我们解决什么问题

传统安全测试的效率瓶颈不在工具，而在“把工具用好”的过程。安全人员需要理解目标、拆解任务、选择扫描器、分析输出、判断误报、整理证据、撰写报告、跟踪复测，这些工作重复且耗时。Veridix 的目标是把这一整条链路交给可审计的 Agent 来完成，让人从繁琐执行中解放出来，把精力放在判断、授权和最终决策上。

它特别适合护网、授权渗透测试、红队演练、代码审计、资产盘点、Web 漏洞验证和长期复测等场景。

## 系统能做到什么

Veridix 不是把模型和工具简单拼在一起，而是构建了一个完整的“理解、执行、验证、交付”闭环。它能够根据任务描述自动规划侦察、扫描、验证和报告流程，在明确授权范围内调用 nmap、nuclei、sqlmap、Metasploit、ZAP、fscan、ffuf、wpscan 等真实安全工具，并通过浏览器代理、容器沙箱、远端节点等多种方式执行测试。

它的每一次运行都不是黑盒。用户可以实时看到 Agent 在做什么、调用了什么工具、观察到了什么、为什么认为某个问题成立，以及最终形成了哪些证据和结论。系统支持人工审批、人工门禁、人工修正，也可以自动沉淀测试经验，让下一次任务更快。

除了执行能力，它还拥有完整的产品形态。Web、TUI、CLI 三端提供一致的使用体验，覆盖任务创建、运行监控、证据审查、知识维护、供应商管理、技能管理、MCP 管理、报告下载和系统诊断。也就是说，它既可以作为团队协作平台使用，也可以作为个人安全工程师的终端助手使用。

## 设计的核心思路

### 模型负责聪明，系统负责可靠

我们相信大模型擅长的是理解任务、提出假设、选择工具和解释结果，而不应该负责存储事实、判断漏洞、控制权限或保证可复现。因此系统把“模型推理”和“工程纪律”分开：模型决定下一步做什么，系统决定这件事能不能做、做得对不对、证据是否成立。

### 每一次执行都是状态机

任务、循环、图和多角色协作都有明确的生命周期和状态。系统允许暂停、恢复、取消、接管和跨进程恢复，任何一次崩溃都不会让任务变成黑盒。所有关键动作都写入事件流，可以从头回放整个决策过程。

### 验证必须由系统完成

模型可以提出漏洞假设，但不能直接宣布漏洞已确认。系统的 Oracle 和证据门禁会根据工具输出、重放结果、回调证据和结构化 finding 判断是否成立。只有证据链完整时，一个 finding 才会进入 verified 状态。这一设计避免了“看起来像成功”的虚假完成。

### 上下文是最小授权，而不是最大转储

每个节点只看到它被允许看到的工具、技能、知识和记忆。系统按角色、任务和 Loop Profile 动态投影上下文，并经过内容信任、注入检测和数据脱敏。外部网页、MCP 结果和工具输出不会被无条件当成指令，而是作为受控数据进入模型。

### 知识、技能和记忆是可持续积累的资产

系统内置了覆盖 ATT&CK、CWE、OWASP、Web 漏洞、身份攻击、云与 AD 后渗透等主题的知识库，并支持多路检索：精确文本匹配、向量语义、知识图谱关联和重排。测试过程中发现的事实会进入项目记忆，跨任务复用，避免重复探索。

技能不是简单的提示词，而是带元数据、工具依赖、回归场景和资源文件的标准化技能包。MCP 连接器让系统可以接入外部能力，同时保持结果可信和可控。

## 先进设计体现在哪里

### Harness-Loop-Graph 三层 Agent 工程

我们把 Agent 执行拆成三个层次：Harness 负责每个节点能看什么、能做什么；Loop 负责一个角色内部的观察-行动-验证闭环；Graph 负责多角色、多阶段的编排。这样既保留了单 Agent 的灵活性，又支持复杂红队流程，同时每一步都可审计、可恢复、可替换。

### 声明式 Loop Profile

每个领域任务都对应一个可版本化的声明式契约，定义允许的工具、技能、知识查询、Oracle、失败策略、重试策略、预算和证据要求。新增一种测试方法不需要改内核，只需要注册一个新的 Profile。

### 真正的多 Agent，而不是多个聊天窗口

多角色协作通过共享 Blackboard 和结构化事实进行，而不是让 Agent 之间互相传递大段文本。每个角色看到独立的工具集和上下文，节点之间通过证据引用沟通。动态 Planner 可以修改图结构，但必须重新通过策略校验。

### 工具链是真实集成的，不是纸面清单

系统直接管理工具 Pack、镜像、健康检查、参数 Schema、风险等级和容器网络。安全工具在统一沙箱中执行，Web 测试走浏览器和代理数据面，ZAP 作为常驻 DAST，远端节点支持 SSH 和签名结果回传。

### 证据和报告是产品能力

系统为每个 finding 生成指纹、证据引用、CVSS 评分、复测状态和风险汇总。报告不是模型编出来的一段文字，而是由真实执行记录生成的交付物。

### 基准驱动演化

系统内置验收、真实工具矩阵、模型对比、RAG 质量、单 Agent 与多 Agent 对比、恢复演练等验证体系。任何复杂设计只有在同场景下产生可量化收益时，才会被保留。

## 典型使用流程

用户首先创建项目并声明目标与授权范围，然后描述任务意图，选择执行模板或 Loop Preset，系统随即创建并启动 Run。

运行过程中，用户可以在 Web 运行控制台或 TUI 中观察事件流、工具调用、上下文投影、图节点状态和预算消耗。遇到高风险工具或需要人工判断的节点时，系统会暂停并请求审批。用户批准后，任务继续执行。

任务结束后，系统把观察和工具输出转换为结构化 finding，经过 Oracle 与证据门禁后进入支持或验证状态。用户可以在证据页审查、批准、拒绝、复测或修正，也可以在漏洞与风险页查看严重度和资产关联，最后从报告页下载可交付的 Markdown、HTML 或 Bundle 报告。

## 适用的部署方式

Veridix 支持轻量桌面部署和服务器部署。桌面模式开箱即用，适合个人测试和演示；服务器模式可以启用 pgvector、Qdrant、Chroma 和 Neo4j 等成熟存储组件，支持更大规模的知识检索与团队使用。

模型端点可以是云端 OpenAI-compatible 服务、企业自有网关，也可以是本地 Ollama 或内置 Lab Provider。系统不绑定某个模型厂商，供应商、模型、嵌入模型和重排模型都可以集中配置和切换。
